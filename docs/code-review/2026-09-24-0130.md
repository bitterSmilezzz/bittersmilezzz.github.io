### P2 — 建议

- **`script.js:118-120`（`dialog` 的点击关闭判定）** — 点击对话框自身的内边距区域也会关闭弹窗。
  - 为什么是问题：`dialog.addEventListener("click", (event) => { if (event.target === dialog) dialog.close() })` 依赖「点到 dialog 元素本身 = 点到遮罩」。但 `<dialog>` 的 `padding` 属于元素自身的盒模型（`styles.css:1218` 是 `padding: 42px`，窄屏 `:1730` 是 `36px 25px 27px`），点到这圈内边距时 `event.target` **就是** `dialog`。所以弹窗内容四周有约 42px 的「点一下就关」区域，用户在弹窗内靠近边缘处想选文字/滚动时很容易误触关闭。真正的遮罩是 `::backdrop` 伪元素，点击它时 `event.target` 同样是 dialog，两者无法用 `event.target` 区分。
  - 建议：用坐标判定代替元素判定——`const r = dialog.getBoundingClientRect(); if (e.clientX < r.left || e.clientX > r.right || e.clientY < r.top || e.clientY > r.bottom) dialog.close()`；或把内边距移到 dialog 内部的一个容器上，让 dialog 自身不留可点的空白。

- **`script.js:1-37`（`projectData`）与 `index.html` 的卡片** — 项目文案存在两份真相，且不一致时静默失败。
  - 为什么是问题：卡片标题/描述/分类写死在 `index.html`（`.project-card` 的 `data-project`、`h3`、`p`、`data-category`），弹窗文案写在 `script.js` 的 `projectData`。两处必须手工保持一致，而 `openProject` 在 `projectData[projectId]` 缺失时直接 `if (!project) return;`——**点了没有任何反应，控制台也没有输出**。将来新增一个项目只改了 HTML 而忘了 JS（或反之），表现就是「这个卡片点不开」，而且没有任何线索指向原因。
  - 建议：加一条启动期自检——遍历 `document.querySelectorAll("[data-project]")`，对每个 `dataset.project` 断言 `projectId in projectData`，缺失时 `console.warn` 并（可选）在页面上标出；更彻底的做法是把卡片渲染也改成数据驱动（`projectData` 为唯一来源，`index.html` 只留容器）。另外 `visibleCount += Number(visible)`（`script.js:74`）用 `Number(true/false)` 计数虽然正确，但改成 `if (visible) visibleCount += 1` 更不容易被误读成「按数量累加」。

- **`README.md`（同步流程）** — 站点文件靠手工同步，没有防漂移手段。
  - 为什么是问题：README 说明「本地编辑源位于配套项目目录；更新网站时，将 `index.html`、`styles.css` 和 `script.js` 同步到本仓库根目录」。三文件手工拷贝，漏一个就会让线上版本内部不一致（例如新 HTML 引用了 CSS 里还不存在的新类名，或 JS 版本落后于 HTML 的 DOM 结构）——这类问题在页面上表现为「样式没生效」或「按钮点了没反应」，不易与「改了但没推」区分开。
  - 建议：在 README 里补一条同步后的自检清单（三个文件的 mtime 应基本一致、`grep` 一下新增类名/`data-*` 在两侧都存在），或给配套项目加一个 `sync.sh` 做拷贝并打印三个文件的校验和，让「是否同步」一眼可判。
